# مستند متطلبات إصلاح خلل تسجيل المتبرع

## المقدمة

عند تسجيل متبرع جديد في نظام BloodConnect، يتم إنشاء حساب المستخدم (user) بنجاح عبر API المصادقة، ولكن لا يتم إنشاء ملف المتبرع (donor profile) في قاعدة البيانات. هذا يؤدي إلى حالة غير متسقة حيث يمتلك المستخدم حساباً ولكن لا يمكنه استخدام ميزات المتبرع لأن ملفه الشخصي غير موجود.

**السبب الجذري:** في ملف `src/pages/Register.tsx` (السطور 95-100)، عند فشل استدعاء `donorsApi.create()`، يتم التقاط الخطأ في كتلة `try-catch` ولكن يتم تجاهله مع رسالة `console.warn` فقط، ثم تستمر العملية وكأن كل شيء نجح. هذا يعني أن المستخدم يُنشأ ولكن ملف المتبرع لا يُنشأ.

**ملاحظة مهمة عن API:** وفقاً لـ `BloodConnect API.json`، endpoint إنشاء المتبرع `POST /api/Donors` يُرجع:
- `201 Created` مع `DonorDtoServiceResponse` عند النجاح
- `400 Bad Request` مع `ObjectServiceResponse` عند الفشل (بيانات غير صحيحة، رقم وطني مكرر، إلخ)

الحقول المطلوبة في `CreateDonorDto`:
- `fullName`, `nationalID`, `gender`, `dateOfBirth`, `phone`, `bloodTypeID`, `city`, `isActive`

**قيد معماري مهم:** لا يوجد حقل `userId` أو `userID` في `DonorDto` أو `CreateDonorDto`. هذا يعني أن API لا يربط تلقائياً بين حساب المستخدم (User) وملف المتبرع (Donor). الربط يتم عبر:
- `donorsApi.getDonorByUserId(userId)` - endpoint موجود في الكود الأمامي ولكن غير موثق في API JSON
- أو عبر مطابقة البيانات (مثل الرقم الوطني أو رقم الهاتف)

هذا القيد يجب أخذه بعين الاعتبار عند تصميم الحل.

**التأثير:** المتبرعون الجدد لا يمكنهم الاستجابة لطلبات الدم أو استخدام أي ميزات تتطلب وجود ملف متبرع في النظام.

## تحليل الخلل

### السلوك الحالي (الخاطئ)

1.1 عندما يقوم مستخدم جديد بملء نموذج التسجيل وإرساله، يتم إنشاء حساب المستخدم عبر `signUp()` بنجاح ولكن يفشل إنشاء ملف المتبرع عبر `donorsApi.create()`، فإن النظام يتجاهل الخطأ ويعرض رسالة نجاح للمستخدم

1.2 عندما يفشل استدعاء `donorsApi.create()` لأي سبب (خطأ في الشبكة، خطأ في الخادم، بيانات غير صحيحة، رقم وطني مكرر)، فإن الكود يطبع تحذيراً في console فقط ويستمر في تنفيذ بقية الكود

1.3 عندما يتم إنشاء حساب المستخدم ولكن يفشل إنشاء ملف المتبرع، فإن المستخدم يُوجَّه إلى لوحة التحكم `/donor/dashboard` رغم عدم وجود ملف متبرع له

1.4 عندما يحاول المستخدم الذي لديه حساب بدون ملف متبرع الوصول إلى ميزات المتبرعين، فإن النظام يفشل في جلب بياناته أو السماح له بالاستجابة لطلبات الدم

### السلوك المتوقع (الصحيح)

2.1 عندما يقوم مستخدم جديد بملء نموذج التسجيل وإرساله، يجب أن ينشئ النظام حساب المستخدم أولاً ثم ملف المتبرع، وإذا فشل إنشاء ملف المتبرع، يجب أن يعرض رسالة خطأ واضحة للمستخدم

2.2 عندما يفشل استدعاء `donorsApi.create()` بعد نجاح `signUp()`، يجب أن يعرض النظام رسالة خطأ مناسبة تشرح المشكلة (مثل: "فشل إنشاء ملف المتبرع"، "الرقم الوطني مسجل مسبقاً"، "خطأ في الاتصال بالخادم") بدلاً من إظهار رسالة نجاح مضللة

2.3 عندما يفشل إنشاء ملف المتبرع، يجب أن يحاول النظام حذف حساب المستخدم الذي تم إنشاؤه (rollback) لتجنب حالة البيانات غير المتسقة، أو على الأقل يجب أن يمنع المستخدم من المتابعة

2.4 عندما يتم إنشاء حساب المستخدم وملف المتبرع بنجاح، يجب أن يعرض النظام رسالة نجاح ويوجه المستخدم إلى لوحة التحكم

2.5 عندما يحدث خطأ في أي خطوة من خطوات التسجيل، يجب أن يبقى المستخدم في صفحة التسجيل مع عرض رسالة الخطأ بوضوح

### السلوك غير المتغير (منع الانحدار)

3.1 عندما يقوم مستخدم بإدخال بيانات تسجيل صحيحة وكاملة، يجب أن يستمر النظام في إنشاء كل من حساب المستخدم وملف المتبرع بنجاح كما هو متوقع

3.2 عندما يقوم مستخدم بإدخال اسم مستخدم مكرر أو بيانات غير صحيحة، يجب أن يستمر النظام في عرض رسائل الخطأ المناسبة كما هو حالياً

3.3 عندما يتم التحقق من صحة البيانات في الواجهة الأمامية (مثل تطابق كلمات المرور، العمر بين 18-65)، يجب أن تستمر هذه التحققات في العمل بنفس الطريقة

3.4 عندما يتم تسجيل متبرع بنجاح، يجب أن يستمر النظام في توجيهه إلى `/donor/dashboard` كما هو حالياً

3.5 عندما يستخدم المستخدم نموذج التسجيل، يجب أن تستمر جميع حقول النموذج والتحققات الأمامية في العمل بنفس الطريقة

## اشتقاق شرط الخلل

### دالة شرط الخلل

```pascal
FUNCTION isBugCondition(X)
  INPUT: X of type RegistrationAttempt
  OUTPUT: boolean
  
  // يُرجع true عندما يتحقق شرط الخلل
  RETURN (X.userCreationSuccess = true) AND (X.donorCreationSuccess = false)
END FUNCTION
```

حيث:
- `RegistrationAttempt` يحتوي على:
  - `userCreationSuccess`: boolean - نجاح إنشاء حساب المستخدم
  - `donorCreationSuccess`: boolean - نجاح إنشاء ملف المتبرع
  - `formData`: object - بيانات النموذج المُدخلة

### خاصية الفحص (Fix Checking)

```pascal
// الخاصية: التحقق من الإصلاح - معالجة فشل إنشاء ملف المتبرع
FOR ALL X WHERE isBugCondition(X) DO
  result ← handleRegistration'(X)
  ASSERT (result.errorDisplayed = true) AND 
         (result.userRedirected = false) AND
         (result.errorMessage != null) AND
         (result.successMessageShown = false)
END FOR
```

**التعريفات الأساسية:**
- **F**: الدالة الأصلية (غير المُصلحة) - الكود كما هو قبل الإصلاح في `Register.tsx`
- **F'**: الدالة المُصلحة - الكود بعد تطبيق الإصلاح

### هدف الحفاظ (Preservation Checking)

```pascal
// الخاصية: فحص الحفاظ - التأكد من عدم تأثر الحالات غير الخاطئة
FOR ALL X WHERE NOT isBugCondition(X) DO
  ASSERT F(X) = F'(X)
END FOR
```

هذا يضمن أن جميع المدخلات غير الخاطئة (التسجيل الناجح الكامل، أو الفشل في إنشاء المستخدم) تتصرف بنفس الطريقة قبل وبعد الإصلاح.

### مثال مضاد ملموس (Counterexample)

**السيناريو 1:** مستخدم يحاول التسجيل ببيانات صحيحة، ولكن API الخاص بإنشاء المتبرع يُرجع خطأ 500 (خطأ في الخادم).

**المدخلات:**
```javascript
{
  username: "ahmad_donor",
  fullName: "أحمد محمد",
  nationalId: "123456789",
  gender: "Male",
  dateOfBirth: "1990-01-01",
  phone: "0912345678",
  bloodType: "A+",
  city: "غريان",
  password: "password123",
  confirmPassword: "password123"
}
```

**السلوك الحالي (F):**
1. يُنشأ حساب المستخدم بنجاح عبر `signUp()`
2. يفشل `donorsApi.create()` بخطأ 500
3. يُطبع `console.warn("Failed to create donor record:", error)`
4. يُعرض: "تم إنشاء حسابك بنجاح! جاري التوجيه..."
5. يُوجَّه المستخدم إلى `/donor/dashboard`
6. **النتيجة:** حساب بدون ملف متبرع ❌

**السلوك المتوقع (F'):**
1. يُنشأ حساب المستخدم بنجاح عبر `signUp()`
2. يفشل `donorsApi.create()` بخطأ 500
3. يُعرض رسالة خطأ: "حدث خطأ أثناء إنشاء ملف المتبرع. يرجى المحاولة مرة أخرى أو التواصل مع الدعم الفني"
4. يبقى المستخدم في صفحة التسجيل
5. يتم إيقاف حالة التحميل
6. **النتيجة:** رسالة خطأ واضحة، لا توجيه خاطئ ✅
